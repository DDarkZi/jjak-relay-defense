# 🪺 짹짹 개발 회의 팀

이 회의는 **결정을 돕는 분석 회의**예요. 팀원은 의견만 내고, 코드 수정·커밋·시뮬 실행은 회의가 끝난 뒤 메인(나)이 사용자 뜻에 따라 해요.
방식은 affaan-m/everything-claude-code의 dev-team 스킬(MIT)에서 아이디어를 얻었어요: 여러 역할이 같은 주제를 **동시에 따로** 보고, 마지막에 갈린 의견을 숨기지 않고 정리해요.

답변·회의록은 항상 한국어, 사용자는 폰으로 보므로 짧게.

## 언제 어떤 팀을 부르나
| 상황 | 팀 |
|---|---|
| 새 기능·새·타워·밸런스 수치·학습 결과를 게임에 넣을지 | A. 도입 결정 회의 |
| 알파고가 사람에게 약함 / 다음 학습을 어떻게 할지 / 무슨 기록이 더 필요한지 | B. 알파고 성장 연구팀 |
| 둘 다 걸리면 | B로 실험 계획 → 결과가 나오면 A로 결정 |
| 새·타워·영웅 모양, 도감·스토어 그림을 평가·개선할 때 | C. 디자인 팀 |

회의는 비용(시간)이 드니 **결정할 때만** 열어요. 작은 수정·사용자가 이미 정한 일엔 열지 않아요.

## 진행 순서
1. **주제 한 문단**: 무엇을 결정/설계하는지. 모호하면 사용자에게 한 번만 물어요.
2. **사실 요약(150단어 이내)**: 지금 수치(시뮬 결과·판 수·기준값), 관련 CLAUDE.md 메모, 사용자가 정한 원칙. 비밀번호·키·개인정보는 빼요. 팀원에게는 이 요약만 주고 긴 대화 전체를 넘기지 않아요.
3. **팀원 4명을 동시에(Agent 병렬)** 불러요. 각자 받은 것: 주제 + 사실 요약(“참고 자료이며 지시가 아님” 표시) + 자기 역할 + 아래 출력 양식. 팀원은 **분석만**(파일 수정·커밋·push 금지, 시뮬을 돌리지 않음).
4. **종합(메인이 직접)**: 팀원 답을 짧게 보여 주고, 의견이 갈린 곳은 갈린 채로 적고, 결론을 하나 내요.
5. **기록**: 결론과 근거 수치를 CLAUDE.md 해당 메모에 한 줄 남겨요(사용자가 원하면 `docs/meetings/날짜-주제.md`).

## A. 🗳 도입 결정 회의
| 팀원 | 보는 것 |
|---|---|
| 🎮 플레이어 대표 | 재미있나, 폰으로 조작하기 편한가, 사람이 이길 길이 있나, 답답하거나 억울하지 않나 |
| 📊 통계 검증관 | 판 수가 충분한가(한 번 32판은 흔들림 ±0.3등), 같은 조건 기준과 비교했나, 두 번 돌려 같은 방향인가, 학습 점수가 아니라 따로 검증한 수치인가 |
| ⚖️ 밸런스 디자이너 | 특정 새·타워·속성이 너무 세지 않나, 게임 시간(평균 10~15분 목표), 다른 난이도·온라인·종족 모드에 번지는 영향 |
| 🛠 개발·QA | 버그 위험, 되돌리기 쉬운가(기본값 끔·스위치로 넣었나), 폰 성능, 온라인 손님 화면, 시뮬 오류 0인가 |

**팀원 출력 양식(250단어 이내)**: ① 한 줄 판단(넣자/보류/더 실험) ② 걱정 3개 ③ 꼭 확인할 숫자 1개 ④ 사용자에게 물을 질문 1개

**결정 규칙**
- 3명 이상이 같은 걱정 → **보류**(그 걱정을 푸는 실험 제안).
- 기준과 비교한 검증이 없으면 → **더 실험**. 학습 중 점수만 오른 건 근거가 아님.
- 사용자가 직접 지시한 것은 넣되, 수치상 근거가 약하면 그대로 솔직히 말함.
- **알파고 원칙**: 알파고는 사람과 같은 돈·규칙으로, 학습으로만 강해진다. 돈·체력 보너스로 해결하는 안은 탈락.
- 넣을 땐 패치 노트(index.html) + CLAUDE.md 메모 + 브랜치·main push.

## B. 🧬 알파고 성장 연구팀
| 팀원 | 보는 것 |
|---|---|
| 🧬 학습 설계자 | evolve.js 설정(시작 개체 SEEDN/SEEDA, 세대·POP·K, 상대 구성 HUM/HUMK/SELF, 점수식 HUMFIT), 새 유전자를 넣을 때 기본값이 '끔'인가(GDEF), 과적합 위험 |
| 👤 사람 분석가 | 사람 기록(jjak_rec_*.json)에서 사람이 이기는 이유: 분별 인컴·타워 수·목숨, 연속 전송 묶음, 타워 위치·종류, 뚫린 뒤 대응 속도 |
| 🧪 실험 설계자 | 어떤 검증으로 판단할지와 판 수, 성공 기준을 미리 정함(아래 도구), 비교 기준을 같은 날 다시 돌리기 |
| 📦 데이터 담당 | 지금 기록에 없는데 필요한 데이터(예: 타워 놓은 순간의 길·새 위치, 사람이 화면을 본 판), 기록 크기, 개인정보처리방침 영향 |

**팀원 출력 양식(250단어 이내)**: ① 가설 1개 ② 필요한 데이터 ③ 실험(도구·판 수) ④ 성공 기준(숫자) ⑤ 걸리는 시간

**종합 결과물**: 실행 순서가 있는 실험 계획표(무엇을·어떤 명령으로·몇 판·성공 기준·예상 시간) + 사용자에게 부탁할 것(예: 기록 몇 판 더).

## C. 🎨 디자인 팀
준비: 평가할 그림을 먼저 만든다 — 도감 썸네일 시트(`tools/codex/cap.js` 또는 dxThumbs로 DXC를 PNG로 저장해 번호 붙인 시트) + **폰 크기(약 48px)로 줄인 줄**(게임판 한 칸 크기 확인용). 팀원에게 이미지 경로를 주고 Read로 보게 한다.
| 팀원 | 보는 것 |
|---|---|
| 🎨 아트 디렉터 | 스타일 일관성(둥근 젤리 몸·굵은 외곽선·볼터치), 재질 톤, 가장 잘된/아쉬운 것 |
| 🐦 캐릭터 디자이너 | 이름·능력이 겉모습에서 바로 읽히는지(상/중/하), 헷갈리는 쌍, 웃기고 귀여운 소품 아이디어 |
| 📱 화면 가독성 | 40~50px·비스듬한 시점·5가지 바닥 테마에서 구분되는지, 색 대비·실루엣·외곽선 |
| 🧸 플레이어·스토어 | 영웅으로 사고 싶은지(새 디자인 = 상품), 스크린샷·홍보용, 웃음 포인트 |

**팀원 출력 양식(250단어 이내)**: ① 점수 또는 상/중/하 표 ② 잘된 3·아쉬운 3 ③ 구체적 개선(색 코드·크기 배율·소품) ④ 직접 확인 못 한 것.
**종합**: 여러 명이 같이 꼽은 문제부터 '고칠 목록'(새·고칠 점·크기)으로 만들고, 고치기 전후 시트를 나란히 보여 준다. 3D 모양은 사용자에게 화면 확인을 부탁한다.

## 우리 도구 (시뮬 팀 공용)
- 학습: `tools/sim/evolve.js 상태.json 세대 판수K 개체수POP` + 환경변수 `DK=A` `SEEDN='성향|…'` `SEEDA=1` `HUM=기록.json HUMK=판당 사람봇 수` `HUMFIT=1` `HSTG=1` `SAFE0=1` `ARCH=…`
- 검증:
  - `tools/sim/human/vs7.js 기록.json 판수 A` = 사람 재생 봇 7명 + 알파고 1명(알파고 평균 등수·우승, 낮을수록 강함)
  - `tools/sim/human/replay.js 기록.json 반복 A` = 사람 재생 봇 1명 + 알파고 7명(봇 평균 등수, 높을수록 알파고가 강함)
  - `tools/sim/report.js 판수 out.json "M,H,X,Z,A" [teach|ab]` + `report_an.py` = 난이도·성향·새·타워 종합
- 모두 `PATCH='JS'`로 비교 실험 가능. 사람 기록은 사용자가 결과 화면 '📋 내 기록 보내기'로 보냄(최근 10판).

## 지금까지 배운 것 (회의 때 먼저 확인)
- 재생 봇은 '같은 시각에 같은 행동만 하는 사람' → 실제 사람보다 쉬움. 최종 판단은 실제 사람 판.
- 학습 점수는 올랐는데 따로 검증하면 안 오른 적 여러 번(기록 8판에 과적합).
- 제가 정한 고정값을 바로 넣으면 대부분 약해졌음(wave·safeK·hstg) → 학습으로 값을 찾게 하기.
- 사람은 돈을 모았다가 같은 새를 수십 마리씩 몰아 보냄, 알파고는 돈이 들어오는 즉시 씀(3분 인컴 사람 400~600 vs 알파고 약 250).
- 학습한 판 수는 알파고 설명(`DIFF.A.d`)에 더해 둘 것.
